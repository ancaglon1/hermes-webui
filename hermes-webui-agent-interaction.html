Hermes WebUI ↔ Agent Interaction

How the Hermes Web UI (this repo) loads, configures, and runs the Hermes Agent in-process. The WebUI imports agent Python modules directly — no subprocess, no external API, no IPC.

2. Agent Discovery & Import

At startup api/config.py searches for the hermes-agent checkout:

1. HERMES_WEBUI_AGENT_DIR env var (explicit override)
2. $HERMES_HOME/hermes-agent          (e.g. ~/.hermes/hermes-agent)
3. ../hermes-agent                     (sibling of this repo)
4. ../../hermes-agent                  (nested parent layout)
5. ~/.hermes/hermes-agent              (common install path)
6. ~/hermes-agent                      (flat home layout)
7. XDG_DATA_HOME / hermes-agent        (Linux standard)
8. /opt, /usr/local, /usr/local/share  (system-wide)

Once found, the agent root is appended to sys.path (at the end, so site-packages pip packages take priority):

if _AGENT_DIR is not None:
    if str(_AGENT_DIR) not in sys.path:
        sys.path.append(str(_AGENT_DIR))

This makes every Hermes agent module importable: run_agent, tools.*, cron.*, hermes_cli.*, agent.*.

3. Chat Lifecycle (Browser → Agent → Browser)

Step 1: POST /api/chat/start

routes.py:_handle_chat_start → _start_run → _start_chat_stream_for_session:

  • Validates session ID, message text, attachments
  • Resolves model/provider/profile via resolve_model_provider()
  • Acquires per-session agent lock (prevents duplicate runs)
  • Creates an SSE queue channel, registers in STREAMS[stream_id]
  • Appends a turn_journal event
  • Spawns a daemon thread running _run_agent_streaming()
  • Returns {stream_id, session_id} immediately

Step 2: GET /api/chat/stream?stream_id=X

Browser opens an EventSource. The server subscribes to the queue and streams events:

SSE EventData ShapeWhen
token{"text": "..."}Per-LLM-token delta
reasoning{"text": "..."}Claude extended thinking / o3 reasoning blocks
tool{"name":"...", "args":..., "preview":"..."}Tool invocation started
tool_complete{"name":"...", "result":...}Tool returned
approval{"command":"...", "pattern_keys":[...]}Dangerous command awaiting approval
clarify{"question":"...", "options":[...]}Agent needs disambiguation
done{"session": {...}, "usage": {...}}Agent finished successfully
error{"message":"...", "trace":"..."}Exception occurred
stream_end{}Clean stream close

Step 3: Inside _run_agent_streaming()

This is the critical bridge, running in a background daemon thread. It lives in api/streaming.py (~line 6330–9900).

3a. Profile & env setup

Sets thread-local HERMES_HOME, provider credentials, terminal config via profile_env_for_background_worker(). Also patches cron module path constants so in-chat cron tool calls resolve to the correct profile.

3b. Model resolution

resolved_model, resolved_provider, resolved_base_url = resolve_model_provider(
    model_with_provider_context(model, provider_context)
)

# Ask the Hermes runtime provider for the real API key + base_url
from hermes_cli.runtime_provider import resolve_runtime_provider
rt = resolve_runtime_provider(requested=resolved_provider,
                              target_model=resolved_model)
resolved_api_key  = rt.get("api_key")
resolved_base_url = _runtime_preferred_base_url(rt, resolved_provider, ...)

# For custom:* providers, also read custom_providers[] from config.yaml

    _resolve_custom_provider_runtime_overrides(...)

3c. AIAgent construction

from run_agent import AIAgent   # lazy import, cached in _get_ai_agent()

agent = AIAgent(
    model=resolved_model,
    provider=resolved_provider,
    base_url=resolved_base_url,
    api_key=resolved_api_key,
    platform='webui',
    quiet_mode=True,
    enabled_toolsets=CLI_TOOLSETS,
    session_id=session_id,
    stream_delta_callback=on_token,       # → SSE 'token'
    reasoning_callback=on_reasoning,       # → SSE 'reasoning'
    tool_progress_callback=on_tool,        # → SSE 'tool' / 'tool_complete'
    clarify_callback=...,                   # → SSE 'clarify'
    tool_start_callback=on_tool_start,      # → SSE 'tool_start'
    tool_complete_callback=on_tool_complete,# → SSE 'tool_complete'
    status_callback=...,                    # → SSE 'status'
    prefill_messages=_prefill_messages,     # recall / contextual prefill
    fallback_model=...,                     # fallback on rate-limit
    request_overrides=...,                  # provider-specific params
)

3d. Agent execution

result = agent.run_conversation(
    user_message=user_message,          # current user turn
    system_message=workspace_system_msg, # workspace + personality
    conversation_history=...,            # prior messages (with sanitization)
    task_id=session_id,                  # NOTE: keyword is task_id, not session_id
    persist_user_message=msg_text,       # plain-text variant for disk
)

While the agent runs, every token, reasoning chunk, and tool invocation flows through the registered callbacks which put() events onto the shared SSE queue.

3e. Post-run writeback

  • Merges agent-produced messages into Session.messages
  • Persists to JSON sidecar (~/.hermes/webui/sessions/{id}.json)
  • Syncs token counts, cost, context-window metadata
  • Stamps tool calls, compression recovery state
  • Handles session-ID rotation on context compression
  • Emits done SSE event with full session + usage payload
  • Starts background title generation if needed

3f. Cleanup (finally block)

finally:
    _clear_thread_env()                          # restore env vars
    with STREAMS_LOCK:
        STREAMS.pop(stream_id, None)             # remove queue
        CANCEL_FLAGS.pop(stream_id, None)         # remove cancel flag
        AGENT_INSTANCES.pop(stream_id, None)      # drop agent ref
        # ... also STREAM_PARTIAL_TEXT, STREAM_REASONING_TEXT, etc.

4. Profile Isolation

The WebUI supports running multiple agent profiles simultaneously. Isolation is entirely in-process:

Per-request TLS

server.py reads the hermes_profile cookie, calls set_request_profile(name). get_active_profile_name() returns the thread-local value, falling back to the process-global _active_profile.

os.environ monkey-patching

profile_env_for_background_worker():

  1. Saves current os.environ for known credential keys
  2. Sets HERMES_HOME to the profile directory
  3. Patches cron.jobs.HERMES_DIR, cron.jobs.CRON_DIR, cron.scheduler._hermes_home module-level constants (snapshotted at import time, so env-var alone is insufficient)
  4. Scrubs credential env vars non-empty in the profile so empty profiles don't inherit server-process API keys
  5. Optionally installs a context-local hermes_constants.set_hermes_home_override() (hermes-agent v0.18.0+) for race-free config resolution on concurrent worker threads
  6. Restores everything in the finally block

6. Session Model

The Session class (api/models.py:1027) is a plain Python class (not a dataclass). Key fields:

session_id, title, workspace, model, model_provider, messages, tool_calls,
created_at, updated_at, pinned, archived, project_id, profile,
input_tokens, output_tokens, estimated_cost,
cache_read_tokens, cache_write_tokens,
personality, active_stream_id,
pending_user_message, pending_attachments, pending_started_at,
context_messages, compression_anchor_*,
context_length, threshold_tokens, last_prompt_tokens,
compression_recovery, truncation_watermark,
gateway_routing, gateway_routing_history,
worktree_path, worktree_branch, worktree_repo_root,
composer_draft, anchor_activity_scenes

Sessions persist as individual JSON sidecars in ~/.hermes/webui/sessions/{id}.json. A _index.json file provides O(1) sidebar listing without scanning all files. An in-memory LRU cache (SESSIONS dict, default cap 100) avoids re-reading recently accessed sessions.

7. The Agent Cache

To avoid re-creating the AIAgent instance for every turn, _run_agent_streaming (line 7807) builds a SHA-256 signature of (model, provider, base_url, api_key, toolsets). If a cached agent with a matching signature exists for this session, it reuses the instance and only refreshes the per-turn callbacks. Otherwise it creates a new agent and evicts the LRU oldest entry.

DecisionChoiceRationale
ServerThreadingHTTPServerPython stdlib, no deps, synchronous agent calls fit threads
StreamingSSE over WebSocketUnidirectional, no upgrade handshake, EventSource is standard
